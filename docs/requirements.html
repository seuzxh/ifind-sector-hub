ifind-sector-hub

需求

为什么要有 ifind-sector-hub：把散落在 monitor 项目里的 ifind 板块数据层，抽成一个语义等价、可多平台复用的公共组件。

背景

monitor（ifind-sector-attribution）项目中，板块/概念数据层的逻辑散落在多处： api_server / realtime_engine / sector_manage / kg_sources / auction_engine 各自裸写 SQL 读取概念字典与成分股；token 刷新靠正则改写 config_local.py； 同步管线（sync_pipeline.py）与业务代码耦合。 当第二个消费平台需要同一份数据时，复制粘贴不可维护——因此将数据层抽离为独立包。

目标

  • 单一职责的数据层组件：数据源客户端（token 生命周期 / 重试 / 分片）、三表存储（字典 / 成分股 / 个股-概念映射）、同步编排，三者可独立使用也可经门面组合。
  • 原语义等价迁移：并发内核、日志行为、SQL 语义自 monitor 原样迁移，monitor 接入替换后行为不变。
  • 多消费方复用：Python SDK（核心）+ 可选 FastAPI 服务层（HTTP 供数），指向任意 SQLite 库文件（monitor 沿用 sector_attribution.db）。
  • token 管理现代化：双检锁刷新替代正则改写配置；FileTokenStore 让同机多进程共用账号时共享刷新结果与 REFRESH_TOKEN 轮换。
  • 裸 SQL 统一入口：5 个只读访问器（概念名映射、最新快照日期、最新股票名映射等）替代消费方各处手写查询。

非目标（本期明确不做）

  • 不部署服务层：FastAPI router 只交付不部署，由消费方自行决定挂载方式。
  • 不做历史数据清理：保留 monitor 的永久缓存快照语义，三表只增不清。
  • 不改变既有表结构：三表 DDL 与 monitor 库文件完全兼容，无需迁移数据。
  • 不修复历史不一致：字典/映射表 YYYY-MM-DD 与成分股表 YYYYMMDD 的日期格式差异原样保留（见设计方案）。

约束

约束说明
核心依赖最小化仅 requests；存储走标准库 sqlite3，测试用标准库 unittest。
可选依赖隔离FastAPI / pydantic 放在 [service] extra，未安装时 import service 模块报 ImportError，不影响库核心使用。
数据域约束只服务沪深北 A 股板块/概念数据：个股后缀 .SH/.SZ/.BJ，概念前缀白名单 700/881/883/884/885/886（861/864/865/871/875 为海外，过滤）。
库文件可插拔SectorStore 可指向任意 SQLite 路径，自建目录、自动建表（CREATE TABLE IF NOT EXISTS）。
配置注入IFindClient 不再读全局配置，base_url / 超时 / 重试 / 批大小全部构造注入；token 解析顺序：显式传入 > 环境变量 IFIND_ACCESS_TOKEN / IFIND_REFRESH_TOKEN。

验收标准

  • 33 个单元测试（6 个测试文件）全部通过：python -m unittest discover -s tests。
  • 覆盖 token 双检/落盘、客户端 401 重试、三表快照读、replace 级联、并发同步、服务层端点。
  • monitor 可用 SectorHub 替换原有散落逻辑，库文件与表结构不变。
